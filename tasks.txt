1. For recorded songs

This is where I'd take strong inspiration from Chord ai.

Use:

Source separation → chord recognition → beat/key analysis

Chord ai explicitly uses instrument separation and can recognize chords, beats, keys and voicings.

For Ahordian, you don't need to reproduce all of Chord ai immediately.

Start with:

Audio file
 ↓
Separate harmonic/instrumental content
 ↓
Chord recognition
 ↓
Beat/downbeat detection
 ↓
Key estimation
 ↓
Chord timeline

Output:

00:00  C
00:02  Am
00:04  F
00:06  G

Key: C Major
BPM: 118

That would be far more useful than the current note-by-note detector for songs.

2. For live guitar playing

This is a different problem.

If someone plays:

C major chord

the system needs to recognize something like:

E3
G3
C4
E4

and infer:

C major

rather than simply saying:

E3 → G3 → C4 → E4

That's where the current Ahordian approach can be improved.

Use a two-stage system
Microphone
   ↓
Pitch / onset detection
   ↓
Detected notes
   ↓
Chord inference engine
   ↓
C major / Am / G7 / etc.

This distinction is critical.

Pitch detection ≠ chord detection.

3. The best open-source component I'd test first: Spotify Basic Pitch

Spotify Basic Pitch

This is probably the first model I'd benchmark against your current detector.

It is an actual neural automatic music transcription model from Spotify, supports polyphonic instruments, detects pitches and pitch bends, and is relatively lightweight. It works best when analyzing one instrument at a time — which fits Ahordian's "user playing guitar" use case well.

It can give you:

Audio
 ↓
Basic Pitch
 ↓
notes + onset + duration + pitch bend

Then Ahordian can infer:

notes = [C, E, G]
        ↓
Chord classifier
        ↓
C major
Very important

I would not replace the whole application with Basic Pitch.

Use it as a detection engine.

4. For recorded multi-instrument songs: MT3 is another candidate

Google Magenta MT3

MT3 is designed specifically for multi-instrument automatic music transcription. It can transcribe multiple instruments from a song rather than assuming a single isolated instrument.

So I'd benchmark:

Input	First choice
Clean live guitar	Basic Pitch
Guitar chord recording	Basic Pitch + chord inference
Full song	MT3 / source separation + chord model
Chord timeline	Dedicated chord recognition
Live chord	Basic Pitch + temporal chord inference

Don't assume MT3 will automatically give you the best chord labels. It's fundamentally a transcription system, whereas Chord ai's product is explicitly optimized around chord/beat/key interpretation.

5. Don't use Basic Pitch alone for chords

This is the trap I want the AI developer to avoid.

If Basic Pitch returns:

C3
G3
C4
E4

you still need to determine:

C

And if it returns:

A2
E3
A3
C4

you need:

Am

So add a Chord Inference Engine.

Something like:

Detected notes
      ↓
Normalize pitch classes
      ↓
Remove low-confidence notes
      ↓
Temporal aggregation
      ↓
Chord template / ML classifier
      ↓
Candidate chords
      ↓
Music-theory scoring
      ↓
Best chord

For example:

C E G
↓
C major       0.94
Am            0.21
Em            0.18
↓
C
6. For solo detection, do NOT treat it like chord detection

This is another important point from the review.

If the user plays a solo:

E → G → A → B → D → E

you want:

E4  0.18s
G4  0.22s
A4  0.15s
B4  0.31s
D5  0.18s
E5  0.42s

plus:

onset
offset
duration
pitch
confidence
pitch bend
vibrato if possible

That's automatic music transcription, not chord recognition.

Basic Pitch is much more appropriate here. It specifically produces note events and supports pitch bends.

8. And add confidence — very important

Don't present uncertain AI predictions as facts.

Instead of:

C Major

show:

9. My recommended architecture

I'd evolve Ahordian toward:

                 Audio Input
                     │
          ┌──────────┴───────────┐
          │                      │
      Live Mic              Audio File
          │                      │
          └──────────┬───────────┘
                     ↓
              Audio Preprocessor
                     │
          ┌──────────┼──────────┐
          │          │          │
       Source     Basic Pitch   Beat
     Separation       / MT3    Tracker
          │          │          │
          └──────────┼──────────┘
                     ↓
              Feature Extraction
                     │
        ┌────────────┼─────────────┐
        ↓            ↓             ↓
    Note Events   Chord Model   Key Model
        │            │             │
        └────────────┼─────────────┘
                     ↓
              Confidence Layer
                     ↓
               Music Context
                     ↓
        ┌────────────┼────────────┐
        ↓            ↓            ↓
    Fretboard     Chords       Timeline

This is the architecture I'd recommend rather than trying to keep improving the current pitch detector with thresholds.

My priority recommendation
P0 — benchmark first

Before changing Ahordian, create a test set:

10 clean single-note guitar recordings
10 guitar chords
10 guitar chord progressions
10 guitar solos
10 full songs

Run:

Current detector vs Basic Pitch vs MT3 where appropriate.

Measure:

Note accuracy
Onset accuracy
Chord accuracy
False positives
Latency
CPU/RAM

Then you have actual evidence.

P1 — implement Basic Pitch for solo/live note detection

This is the easiest high-value improvement.

P2 — implement chord inference

Basic Pitch output → chord recognition.

P3 — dedicated recorded-song chord pipeline

Source separation + chord model + beat/key.

P4 — UI

Turn Detector into:

Song Analysis / Live Guitar / Solo Transcription / Chord Detection

One thing I would NOT do

I would not attempt to clone Chord ai's entire AI stack.

We don't know their proprietary model implementation. Their public description says they use "recent deep learning algorithms," but it doesn't provide enough technical detail to reproduce their exact system.

Instead:

Use Chord ai as the product/UX benchmark, and use open models as Ahordian's underlying technology.

The strongest starting combination I see is:

Basic Pitch + dedicated chord inference + beat/key detection + optional source separation.
