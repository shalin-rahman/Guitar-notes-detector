2. There is a more important audio bug Batch A doesn't address

This is the thing I would add to the plan.

Currently:

startSession(sessionType, { exclusive: true })

does:

activeSessions.clear()
activeSessions.add(newSession)

It does not actually stop the previous audio engine.

Example:

Metronome playing
      ↓
Start Jam
      ↓
AudioSessionManager clears "Metronome"
      ↓
Jam becomes active
      ↓
BUT Metronome may still be physically playing

So the session state and actual audio can diverge.

That's a real architectural bug.

Fix this before calling Batch A complete.

The manager should own stop callbacks:

SessionManager

METRONOME
   → stop callback

JAM_TRACK
   → stop callback

EAR_TRAINING
   → stop callback

TAB_PLAYER
   → stop callback

Then:

startSession(JAM, exclusive)
        ↓
stop currently active sessions
        ↓
clear session state
        ↓
start Jam

This makes your original requirement:

"override if any other is played"

actually true.

13. I would improve the replay data structure

Current history is just:

["C4", "E4", "G4", "A4"]

That is enough for V1.

But the original request specifically mentions replaying the detected sequence, so timing matters.

Eventually use:

{
    note: "C4",
    timestamp: performance.now()
}

Then normalize:

10.00 → 0.00
10.43 → 0.43
10.91 → 0.91
11.37 → 1.37

The replay then preserves the user's rhythm rather than playing every note at a fixed 500ms.

I would make this part of Batch D.
